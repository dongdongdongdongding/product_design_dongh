# 플랫폼 원칙 — Apple HIG 중심, 웹 관리자 화면으로 옮겨 쓰기

원칙 문서는 바뀐다. 사용자가 "iOS 느낌"이나 "HIG대로"를 요구하면 최신 Apple Human Interface Guidelines(developer.apple.com/design/human-interface-guidelines)를 먼저 확인하고, 아래 요약과 다르면 문서를 따른다.

## 1. HIG의 바탕 — 위계 · 조화 · 일관성

| 원칙 | 뜻 | 관리자 화면에서 |
|---|---|---|
| 위계(Hierarchy) | 중요한 것이 먼저 보이고, 장식이 내용을 가리지 않는다 | 화면마다 주 작업 1개(주 버튼 1개). 제목 → 요약 수치 → 목록 · 상세 순. 테두리 · 그림자보다 여백과 글자 무게로 묶는다 |
| 조화(Harmony) | 하드웨어 · 시스템과 어울리는 모양 · 간격 | 모서리 반경 · 간격을 몇 단계로 고정(4 · 8 · 12 · 16 · 24 · 32). 같은 종류는 같은 반경 |
| 일관성(Consistency) | 플랫폼 관례를 따라 배울 것을 줄인다 | 같은 동작은 같은 자리 · 같은 이름(저장은 항상 오른쪽 아래, "삭제"와 "제거"를 섞지 않음) |

이전 판의 명료함(Clarity) · 존중(Deference) · 깊이(Depth)도 같은 말이다: 글자는 읽히게, UI는 내용을 위해 물러서고, 겹침(시트 · 팝오버)은 맥락을 잃지 않게.

## 2. 구체 수치 (iOS 기준 → 웹 환산)

| 항목 | iOS HIG | 웹 관리자 화면 기본값 |
|---|---|---|
| 터치 · 클릭 영역 | 최소 44×44pt | 버튼 높이 32~40px, 표 행 40~48px, 아이콘 버튼도 클릭 영역 32px 이상 |
| 본문 글자 | Body 17pt, 보조 15 · 13 · 12pt | 본문 14px(정보 밀도 높은 표 13px), 제목 단계는 20 · 16 · 14로 3단 이하 |
| 글꼴 | SF Pro (한글 시스템 글꼴) | 운영 사이트 글꼴, 없으면 Pretendard · Apple SD Gothic Neo · Malgun Gothic 순 |
| 간격 | 8pt 기준 격자, 기본 여백 16 · 20pt | 8px 격자: 카드 안 16~24, 카드 사이 16~20, 구역 사이 24~32 |
| 모서리 | 연속 곡률, 컨트롤 크기에 비례 | 입력 · 버튼 6~8px, 카드 10~12px, 팝업 12~16px |
| 색 | 시스템 색 + 의미 색(빨강 = 파괴적 동작) | 주 색 1개 + 의미 색 4개(성공 · 주의 · 위험 · 정보). 강조는 면적이 아니라 대비로 |
| 그림자 | 거의 쓰지 않음, 겹침에만 | 카드 그림자는 약하게(투명도 4~8%) 또는 1px 선. 팝업 · 메뉴처럼 떠 있는 것만 진하게 |
| 다크 모드 | 의미 색 기반 자동 | 요구에 있을 때만. 있으면 토큰을 의미 이름으로 둬서 값만 바꾼다(`tokens.md`) |

## 3. 화면 패턴 대응

| HIG 패턴 | 언제 | 웹 관리자 화면 대응 |
|---|---|---|
| 내비게이션 계층(Navigation stack) | 목록 → 상세 | 브레드크럼 + 뒤로. 상세는 별도 페이지 또는 오른쪽 패널(목록 유지) |
| 시트(Sheet) | 현재 맥락을 유지한 짧은 작업 | 오른쪽 패널 · 팝업. 입력 6개 이하 |
| 전체 화면 모달 | 길고 독립적인 작업 | 별도 페이지(등록 · 수정 폼). 이탈 시 "작성 중인 내용" 확인 |
| 알림(Alert) | 되돌릴 수 없는 동작 확인, 중요한 오류 | 확인 팝업: 결과를 말하는 제목("예약 3건을 취소할까요?"), 파괴적 버튼은 빨강 · 기본 선택 아님 |
| 액션 시트 · 메뉴 | 같은 대상에 여러 동작 | 행 끝 "더보기" 메뉴, 대량 선택 시 상단 작업 바 |
| 세그먼트 컨트롤 | 같은 데이터의 다른 보기 2~4개 | 목록/지도/달력 전환, 상태 필터 |
| 빈 상태 · 로딩 | 데이터가 없거나 기다릴 때 | 이유 한 줄 + 다음 행동 버튼, 스켈레톤(3초 이상이면 진행 표시) |

## 4. 다른 체계와 함께 쓸 때

- **Material 3**: 상태 레이어(hover 8% · focus · pressed 10% 등), 컴포넌트 상태 이름이 정리돼 있어 `components.md`의 상태 열 기준으로 쓰기 좋다.
- **KRDS(대한민국 정부 디자인 시스템)**: 공공 서비스면 우선 검토 — 필수 표기, 오류 안내, 접근성 요건이 구체적이다.
- 기업 디자인 시스템(Carbon · Atlassian · Polaris · Ant): 데이터 표 · 필터 · 대량 작업 · 빈 상태 패턴의 레퍼런스로.

## 5. 점검 질문 (시안마다)

1. 주 버튼이 하나인가, 그것이 이 화면의 주 작업인가?
2. 제목 단계가 3단 이하이고, 같은 단계는 같은 크기 · 무게인가?
3. 간격이 8px 격자 값만 쓰는가(`design_tokens.py inventory`로 확인)?
4. 클릭 영역 32px 이상, 표 행 40px 이상인가(밀도 '촘촘'을 고른 경우 제외)?
5. 파괴적 동작이 빨강 · 확인 팝업 · 기본 선택 아님인가?
6. 떠 있는 것(팝업 · 메뉴)만 그림자가 진한가?
7. 본문 대비 4.5:1, 큰 글자 · 아이콘 · 입력 테두리 3:1인가(`design_tokens.py contrast`)?
