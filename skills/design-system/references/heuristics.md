# 휴리스틱 평가 — 닐슨 10원칙을 관리자 · 업무 화면에 맞춰

초안을 사용자에게 보여 주기 **전에** 스스로 한 번, 검토 회차마다 바뀐 화면만 다시 한다. 결과는 위반 표로 남기고, 심각도 3 이상은 고친 뒤에 보여 준다.

## 원칙별 점검 항목

| # | 원칙 | 업무 화면에서 볼 것 |
|---|---|---|
| H1 | 시스템 상태가 보인다 | 저장 · 처리 중 표시, 마지막 갱신 시각, 목록 건수, 필터가 걸려 있다는 표시, 단계형 작업의 현재 위치 |
| H2 | 현실 세계와 맞는 말 | 업무 용어(원본 자료 · 운영 사이트의 용어) 그대로. 코드값 · 영문 상태값(PENDING)을 그대로 노출하지 않음 |
| H3 | 사용자 통제와 자유 | 취소 · 되돌리기, 작성 중 이탈 경고, 대량 작업 후 되돌릴 길, 필터 초기화 |
| H4 | 일관성과 표준 | 같은 동작 같은 이름 · 자리, 같은 상태 같은 색 배지, 날짜 · 숫자 형식 통일 |
| H5 | 오류 예방 | 필수 표시, 입력 형식 안내, 위험 동작 확인, 불가능한 선택 비활성화(이유 표시), 중복 등록 막기 |
| H6 | 기억보다 인식 | 선택지를 보여 주기(코드 직접 입력 대신 선택), 최근 · 자주 쓰는 값, 상세에서 목록 맥락 유지 |
| H7 | 유연성과 효율 | 숙련자용 지름길: 대량 선택 · 일괄 처리, 저장된 필터, 표 정렬 · 열 고정, 키보드 이동 |
| H8 | 미적이고 최소한의 디자인 | 화면마다 주 작업 하나, 장식 면 · 아이콘 남용 없음, 정보 위계가 글자 크기 · 무게 · 여백으로 드러남 |
| H9 | 오류 인식 · 진단 · 복구 | 오류 문구 = 무엇이 · 왜 · 어떻게 고치나, 입력 바로 아래, 서버 오류 시 다시 시도 · 입력 보존 |
| H10 | 도움말과 문서 | 처음 쓰는 화면의 짧은 안내, 복잡한 규칙의 툴팁 · 설명 링크, 빈 상태에서 다음 행동 |

## 심각도

| 등급 | 뜻 | 처리 |
|---|---|---|
| 4 | 작업을 못 끝낸다 · 데이터를 잃는다 | 보여 주기 전에 고친다 |
| 3 | 자주 막히거나 잘못 처리한다 | 보여 주기 전에 고친다 |
| 2 | 느려지거나 헷갈린다 | 이번 회차에 고치거나 이유를 적고 남긴다 |
| 1 | 겉모양 | 시간이 나면 |

## 함께 볼 것

- 상태 화면: 빈 상태 · 로딩 · 오류 · 권한 없음 · 저장 실패 · 동시 수정 충돌을 공통 상태 화면이나 각 화면 states에 둔다(H1 · H9).
- 예외(EX)와 검수(AT): 위반을 고치며 생긴 규칙은 기능정의서 예외 · 검수에도 넣는다 — 화면만 고치고 문서를 비워 두지 않는다.
