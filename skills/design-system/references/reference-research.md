# 외부 레퍼런스 조사

목적: 시안 비교 · 초안을 "일반 관리자 틀"이 아니라 **이 업무에서 검증된 화면 구조** 위에 그리는 것. 사용자에게 묻기 전에 먼저 찾는다.

## 1. 무엇을 찾나

요구 목록에서 화면 유형과 핵심 동작을 뽑고(예: "시설 예약 승인", "지도 위 구역 그리기", "일정 충돌 확인"), 유형마다 아래를 찾는다.

| 종류 | 찾는 곳 (예) | 가져올 것 |
|---|---|---|
| 같은 업무의 실제 서비스 | 국내외 동종 서비스의 관리자 화면 · 도움말 문서 · 사용 설명서 캡처, 공공 서비스 | 메뉴 구조, 목록 열 구성, 상태 단계, 승인 · 반려 흐름 |
| 공개 디자인 시스템 | Apple HIG, Material 3, KRDS(대한민국 정부 디자인 시스템), Carbon(IBM), Atlassian, Polaris(Shopify), Ant Design, GitHub Primer | 컴포넌트 구성 · 상태 · 간격 체계 · 데이터 표 패턴 · 빈 상태 · 오류 문구 |
| 패턴 모음 | 화면 패턴 갤러리(Mobbin 등 공개 페이지), 디자인 시스템의 패턴 문서(필터 · 대량 작업 · 마법사 대신 단일 페이지 등) | 같은 문제를 푼 2~3가지 방식 → 시안 A/B/C의 축 |
| 규정 · 지침 | 웹 접근성(KWCAG 2.2 · WCAG 2.2), 행정 · 공공 서비스 UI 지침(공공 사업일 때) | 필수 표기, 대비, 키보드 · 포커스 |

검색어는 업무어 + 화면어로 만든다: "예약 관리 관리자 화면 승인", "admin dashboard reservation approval table filter", "map polygon drawing admin UI", "data table bulk actions pattern design system".

## 2. 도구

- 웹 검색(WebSearch) · 페이지 읽기(WebFetch)가 있으면 쓴다. 공식 디자인 시스템 문서를 먼저, 블로그 · 갤러리는 보조로.
- 브라우저 도구가 있으면 공개 페이지를 열어 화면 구조를 확인한다. **로그인이 필요한 곳은 들어가지 않는다**(사용자가 직접 로그인해 캡처를 줄 수 있다).
- 검색 도구가 없으면(Codex 등 오프라인): 이 파일의 디자인 시스템 목록과 `platform-hig.md`의 원칙으로 대신하고, "외부 검색 안 함"이라고 보고하며 사용자에게 참고 링크 · 캡처를 요청한다.

## 3. 정리 — `research/레퍼런스.md`

| # | 출처(링크) | 종류 | 화면 · 패턴 | 가져올 것(구조) | 가져오지 않을 것 | 적용 화면 |
|---|---|---|---|---|---|---|
| 1 | | 서비스 / 디자인 시스템 / 패턴 / 지침 | | | 색 · 로고 · 문구 | F1 · B1 |

- 5~10건. 같은 문제를 다르게 푼 사례를 나란히 둔다 — 이것이 시안 A/B/C의 근거가 된다.
- 문구 인용은 짧게(한 문장 이하), 이미지 · 로고는 저장 · 재사용하지 않는다. 링크와 요약만.
- 시안 · 초안 노트에 "근거: 레퍼런스 ②④"처럼 번호로 잇는다.
