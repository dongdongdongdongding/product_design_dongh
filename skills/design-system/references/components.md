# 컴포넌트 정리

화면 시안에서 반복되는 부분을 컴포넌트로 묶고, 상태별 모양을 한 장에 모은다. 개발자는 이 표로 무엇을 만들지 알고, 디자인 캔버스는 `DS-components` 보드로 보여 준다.

## 1. 목록 뽑기

시안 도구(`project.js`의 `shell` · `card` · `field` · `seg` · `kpi` · `mapBox`)와 theme.css 클래스(`.btn` · `.inp` · `.sel` · `.tg` · `.t` · `.modal` · `.toast` · `.msg` …)가 곧 후보다. 화면에서 3번 이상 나오면 컴포넌트로 본다.

기본 목록(업무 · 관리자 화면):

| 묶음 | 컴포넌트 |
|---|---|
| 동작 | 버튼(주 · 보조 · 위험 · 텍스트 · 아이콘), 더보기 메뉴, 대량 작업 바 |
| 입력 | 텍스트 입력, 선택(드롭다운), 검색, 날짜 · 기간, 체크 · 라디오, 토글, 세그먼트, 파일 첨부, 지도 위치 선택 |
| 표시 | 상태 배지, 수치 카드(KPI), 표(정렬 · 선택 · 빈 행), 페이지 이동, 탭, 브레드크럼, 진행 단계 |
| 겹침 | 팝업(확인 · 폼), 오른쪽 패널, 토스트, 툴팁 |
| 상태 | 빈 상태, 로딩(스켈레톤), 오류 안내, 권한 없음 |
| 틀 | 사이드 메뉴, 상단 바, 페이지 머리(제목 · 작업 버튼), 카드 |

## 2. 상태 열

컴포넌트마다 해당하는 것만: 기본 · 마우스 올림 · 포커스(키보드) · 누름 · 선택됨 · 비활성(이유) · 오류 · 읽기 전용 · 로딩.
포커스는 반드시 보이게(2px 외곽선 · 대비 3:1). 비활성은 흐리게만 하지 말고 이유를 툴팁 · 안내로.

## 3. 기록 — `design-system/components.js`

project.js와 같은 범위에서 읽히므로 시안 도구를 그대로 쓴다:

```js
const COMPONENTS = [
  { name: '버튼', desc: '주 버튼은 화면마다 하나', states: [
    { label: '주', html: '<span class="btn pri">저장</span>' },
    { label: '보조', html: '<span class="btn">취소</span>' },
    { label: '위험', html: '<span class="btn danger">삭제</span>' },
    { label: '비활성', html: '<span class="btn pri" style="opacity:.45">저장</span>' } ] },
  { name: '입력', states: [
    { label: '기본', html: field('시설명', '캠핑장 A구역', { req: 1 }) },
    { label: '오류', html: field('수용 인원', '0', { err: 1, msg: '1명 이상 입력하세요' }) } ] }
];
```

## 4. 화면설계서 · 개발 전달용 표 (기능정의서 부록이나 `research/컴포넌트.md`)

| 컴포넌트 | 쓰는 화면 | 상태 | 크기 · 간격(토큰) | 규칙 |
|---|---|---|---|---|
| 버튼 · 주 | F1 · F2 · B2 | 기본 · 올림 · 포커스 · 비활성 | 높이 36, `radius.md`, `color.primary` | 화면당 1개, 오른쪽 끝 |

## 5. 캔버스에서 공통 컴포넌트로

디자인 캔버스 다듬기 단계에서 반복 부분(사이드바 · 지도 · 표 머리)은 `dc-import` 공통 컴포넌트로 묶는다(`design-canvas` 스킬 2절). 컴포넌트 표의 이름과 같게 짓는다.
