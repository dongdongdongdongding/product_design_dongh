# 디자인 질문 → 디자인 브리프

〔2/7 디자인 질문〕 목적: 초안을 한 번에 사용자 기대에 가깝게 그리는 것. 질문은 짧게, 모르면 기본값으로 간다.

## 1. 먼저 읽고, 남은 것만 묻는다

질문 전에 이미 있는 근거를 본다. 거기서 답이 나오면 묻지 않고 "○○에서 확인: …"으로 알린다.
- 운영 사이트가 있으면 `source-intake` 3절로 색 · 글꼴 · 카드 · 버튼 · 입력 높이를 잰다(가장 강한 근거).
- 기획서 · 화면 캡처 · 참고 SB에서 레이아웃 · 메뉴 · 항목 배치를 읽는다.
- 디자인 가이드 · Figma 링크가 있으면 토큰을 그대로 쓴다.

## 2. 질문 (references/design-questions.md에서 고른다)

한 번에 최대 7개. 그룹 A는 거의 항상, B · C는 해당할 때만. **D(상태 · 규칙)는 묻지 않고 기본값으로 정해 브리프에 적고** "바꿀 것이 있으면 말해 주세요"라고만 덧붙인다(실제 개발 문서면 브리프 D칸을 꼭 채운다). 항목마다 기본값을 붙여 "기본값"이라고만 답해도 되게 한다.

| 그룹 | 언제 | 예 |
|---|---|---|
| A. 기준 · 톤 | 항상 | 따를 사이트 · 서비스, 톤(업무형 담백 / 친근 / 공공 기관형), 브랜드 색 |
| B. 틀 · 밀도 | 운영 사이트가 없을 때 | 사이드바 · 상단 메뉴, 표 밀도, 기준 해상도 |
| C. 패턴 | 화면 종류에 따라 | 목록(표 / 카드), 등록(페이지 / 팝업 / 오른쪽 패널), 지도 · 차트 유무 |
| D. 상태 · 규칙 | 실제 개발 문서일 때 | 필수 표시, 오류 문구 위치, 빈 상태, 삭제 확인, 접근성 수준 |

선택형 질문 도구가 있으면 A·B를 먼저 묻고(4개씩), 없으면 번호 목록으로 한 번에 묻는다. 시안 그림이 도움이 되면 선택지마다 ASCII 배치나 작은 미리보기를 붙인다.

## 3. 브리프 정리 → 확인

플러그인 루트의 `templates/intake/디자인브리프.md` 양식으로 `<작업 폴더>/research/디자인브리프.md`를 쓰고, 값을 바로 `spec-kit/theme.css`에 넣은 뒤(클래스 이름은 유지, 값만) 핵심 6~8줄만 보여 준다:

```
기준: ○○ 관리자 사이트 (측정 2026-10-29) · 톤: 업무형 담백
색: 주 #2E9E6B · 보조 #7987A1 · 위험 #FF3366 · 글꼴 Pretendard 14px
틀: 왼쪽 사이드바 240 · 상단 60 · 1440×900
목록: 표(행 40px) · 등록: 별도 페이지 · 확인: 팝업
상태: 필수 * · 오류는 입력 아래 빨간 글씨 · 빈 상태 안내 한 줄
근거 없는 기본값: 3개 (브리프 '가정' 칸)
```
- 사용자가 질문에 직접 답했으면: "이 방향으로 초안을 그릴까요?" — 고치면 반영한다.
- "기본값"이라고 했으면: 요약만 보여 주고 확인 없이 3단계로 간다("초안을 보고 바꾸셔도 됩니다").
- 어느 쪽이든 `progress.md` 2단계를 체크한다.

다음 예고: "〔3/7 초안〕 핵심 화면 ○개를 먼저 그려 보여 드립니다."

## 원칙

- 운영 사이트의 실제 값 > 디자인 가이드 > 사용자 답 > 기획 PPT 장식 > 기본값 순으로 따른다. 충돌하면 사용자에게 어느 쪽인지 묻는다.
- 질문이 길어지면 묻지 말고 기본값으로 초안을 먼저 보여 주는 편이 낫다. 그림을 보면 답이 빨라진다(4단계에서 고친다).
- 색을 고르면 대비(본문 4.5:1)를 확인하고, 모자라면 알린다.
