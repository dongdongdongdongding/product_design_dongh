# 플로우 맵 아티팩트

엔진(`engine/`)은 고치지 않는다. 프로젝트 폴더의 네 파일만 쓴다.

| 파일 | 내용 |
|---|---|
| `kit.json` | 제목 · 부제 · 문서 폴더 · 문서 이름 · expect · 출력 파일 |
| `theme.css` | 시안 테마(`.scr` 아래 클래스). 근거 노트의 측정값으로 바꾼다 |
| `project.js` | `PROJECT` · `SHARE` · `H` · `SCREENS` · `FLOWS` · `ISSUES` |
| `sb-pages.js` | 화면설계서 탭 (`sb-screen-spec` 스킬) |

빌드: `python -I scripts/build_kit.py <프로젝트 폴더>` → `flowmap.html`. 문서 표는 빌드가 DOCDATA로 넣는다.

## project.js 쓰는 법 (자세한 계약은 references/project-contract.md)

- **시안 `H[id] = () => html`**: `shell(메뉴키, head([경로]) + 본문)`으로 기존 사이트 틀(사이드바 · 상단 바 · 브레드크럼 · 하단)을 쓰고, 본문은 theme.css 클래스로 짠다(카드 `.c`, 제목 `.ch`, 입력 `.inp`, 드롭다운 `.sel`, 토글 `.seg`, 배지 `.tg`, 표 `table.t`, 목록 `.lbox .li`, 안내 `.note`, 지도 `.mapw`). 팝업 화면은 뒤 화면을 `<div class="dimmed">` + `nogo(H.X())`로 깔고 `.shade` · `.modal`을 덮는다.
- **연결**: 다른 화면으로 가는 버튼 · 링크에 `data-go="화면ID"`. 사이드 메뉴는 `data-nav`. 연결선 · 프로토타입 · 화면설계서의 "들어오는 곳 · 나가는 곳"이 모두 여기서 나온다.
- **SCREENS**: id · flow · kind · title · purpose · feat(기능 ID — 문서와 같게) · parts · states · rules · ex · at. 화면 아래 기능정의 카드와 인스펙터가 이것을 보여 준다.
- **FLOWS**: 메뉴(섹션)별 화면 순서. 캔버스의 행이 된다.
- **ISSUES**: 검토에서 찾은 문제(id · scr · sev · st · t · src · p · fx · rest). 화면 핀과 왼쪽 "검토 이슈" 탭.
- **PROJECT.transData**: 연결선 정보 패널의 "넘기는 값" (`'R1>P2': '구역 ID · 시나리오 ID'`).

시안은 배포 사이트 테마로만 그리고, 1440×900 안에 들어가게 한다(넘치면 검수에서 잡힌다). 실제 개발 문서라면 시연 · 예시 배지를 넣지 않는다.

## 연결선 (엔진 기능)

툴바에 우회 · 화면 앞 · 화면 뒤 모드가 있다. 우회는 화면 사이 통로와 섹션 제목 아래 띠로만 꺾어 지나가 화면을 가리지 않는다. 연결선을 누르면 오른쪽 패널에 출발 · 누르는 곳 · 도착 · 넘기는 값 · 같은 두 화면 사이 다른 연결이 나오고 출발 화면의 버튼이 강조된다.

## 게시

1. `artifact-qa`로 점검 0건을 확인한다.
2. Artifact 도구로 `flowmap.html`을 게시한다(첫 게시는 icon `map`). 같은 파일 경로로 다시 게시하면 같은 URL이 갱신된다.
3. 링크 공유 중이면 즉시 반영된다고 알린다. 거절되면 최신본을 읽어 병합한다.

## 고칠 때

- 화면 하나를 고치면: project.js의 H · SCREENS → 필요하면 sb-pages.js 해당 페이지의 마커 · 설명 → 문서(12.2 필드 등) → 빌드 → 검수.
- 기능을 추가하면: 문서(기능 · 예외 · 검수 · WBS · 요구 추적) → SCREENS.feat → kit.json expect → 빌드.
- 문자열을 바꿀 때는 같은 문자열이 다른 화면에 있는지 먼저 센다.
