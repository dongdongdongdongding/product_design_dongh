# 초안 → 검토 · 개선 → 확장

초안도 `project.js` · `docs/`에 쓰고 같은 엔진으로 빌드한다. 승인된 초안은 그대로 전체 버전의 일부가 된다.

## 〔3/7 초안〕 만들기

1. **무엇을 그릴지 고른다** — 요구 목록에서 사용자가 가장 오래 머무는 화면, 입력이 가장 많은 화면, 처음 보는 패턴(지도 · 승인 흐름 등)을 2~4개. 한 흐름의 앞뒤(목록 → 상세)는 되도록 함께 고른다. 고른 이유와 **아직 안 그린 화면 목록**을 함께 알린다. 사용자가 지정하면 그것을 그린다.
2. **문서 뼈대** — `docs/` 3종에 변경 이력, 화면 목록(5.1), 요구 추적표(5.2), 고른 화면의 기능 ID 표만 채운다(나머지 절은 비워 둔다). `check_docs.py`가 통과할 만큼만.
3. **시안** — 브리프 · theme.css로 `H` · `SCREENS` · `FLOWS`를 쓴다. 버튼에 `data-go`를 달아 초안끼리 연결한다. 아직 없는 화면으로 가는 버튼은 `data-go`를 달지 않고 `ISSUES`에 "미정 화면" 이슈(`st: 'ask'`)로 남긴다.
4. **빌드 · 보여 주기** — `build_kit.py`. Artifact가 있으면 게시하고 링크를, 없으면 진입 스킬 "도구가 다를 때" 표대로 로컬 서버 주소나 파일을 준다. 캡처 도구가 있으면 화면 캡처를 함께 보여 준다.
5. **질문** — 아래 형식으로 묻는다.

```
〔3/7 초안〕 화면 3개(F1 시설 목록 · F2 시설 등록 · B2 예약 상세)를 그렸습니다: <링크>
보시고 이렇게 답해 주세요(일부만 답해도 됩니다):
  유지  — 좋은 점
  수정  — 화면 ID + 무엇을 (예: "F2 위치 지도를 왼쪽으로")
  추가  — 빠진 항목 · 화면
  질문  — 이해 안 되는 것
"좋아요"라고만 하면 이 방향으로 전체 화면을 그립니다.
```

## 〔4/7 검토 · 개선〕 반복

1. 피드백을 한 줄씩 나눠 표로 되묻지 말고 바로 분류해 반영한다: 화면(H · theme) / 흐름(data-go · FLOWS) / 내용(문서 · 기능 ID) / 범위(요구 추가 · 삭제 → 1단계 근거노트도 갱신).
   - **아직 안 그린 화면에 대한 피드백**(예: 초안에 없는 목록 화면에 "필터 추가")은 그 화면을 이번 회차에 새로 그려 반영한다.
   - **요구 목록에 없는 새 요구**는 추가하되 보고에 "범위 추가: … (기능 ID · 공수 영향 추정)"으로 따로 표시해 되돌릴 수 있게 한다. 공수가 1인일 이상 늘면 반영 전에 한 줄로 확인한다.
2. 해석이 두 갈래면 두 안을 작게 만들어 보여 주거나(나란히 비교) 한 번만 묻는다.
3. 반영 기록을 남긴다 — 의미 있는 변경은 `ISSUES`(`src: '검토 n회차'`, `st: 'done'`)와 기능정의서 변경 이력에, 회차 요약은 `progress.md` 피드백 표에.
4. 다시 빌드해 보여 주며 "n회차 반영: 수정 3 · 추가 1 · 보류 1(이유)"로 알린다.
5. 회차가 3번을 넘거나 같은 곳을 되돌리면, 결정할 기준(예: "목록 우선 vs 지도 우선")을 짚고 선택을 받는다.

**확인 지점**: "이 방향으로 나머지 화면 ○개를 그릴까요?" → 승인되면 `progress.md` 4단계 체크.

## 확장 (5단계로 넘기기)

- 남은 화면 목록과 순서를 보여 준다(메뉴 순 · 흐름 순). 많으면 메뉴 단위로 나눠 보여 주며 진행한다.
- 초안에서 정한 패턴(목록 · 폼 · 팝업 · 상태 표시)을 나머지 화면에 같게 쓴다. 다르게 해야 하면 이유를 적는다.
- 문서 3종의 나머지 절(예외 · 검수 · 12장 · 13장 · WBS)은 `spec-docs`, 연결 · 인스펙터 · 게시는 `flowmap-artifact`로 이어 간다.
