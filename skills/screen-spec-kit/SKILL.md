# 화면 설계 산출물 키트

원본 자료 → 근거 노트 → 개발 문서 → 화면 시안 → 플로우 맵 · 화면설계서 → 디자인 캔버스 → 검수 → 게시. 산출물이 서로 이어져 있어 하나를 고치면 뒤 단계도 다시 만든다. 이 스킬은 순서와 원칙을 잡고, 단계별 방법은 하위 스킬에 있다.

플러그인 루트(이 파일 기준 `../../`):
- `engine/` 공통 엔진 (캔버스 · 우회 연결선 · 인스펙터 · 문서 패널 · SB 엔진 · 지도 기준 · 최종 검증). 프로젝트마다 고치지 않는다.
- `templates/project-starter/` 새 프로젝트 시작 틀 (kit.json · theme.css · project.js · sb-pages.js · docs/).
- `examples/demo-park/` 끝까지 만든 가상 예시 한 벌(도시공원 시설 예약 관리).
- `scripts/` build_kit.py · check_docs.py · export_design.mjs · audits/*.js.

## 단계와 하위 스킬

| 단계 | 결과 | 하위 스킬 |
|---|---|---|
| 1. 원본 읽기 · 사이트 측정 | `research/근거노트.md`, 테마 값 | `source-intake` |
| 2. 개발 문서 | `docs/` 3종 | `spec-docs` |
| 3. 화면 시안 · 플로우 맵 | `project.js` · `theme.css` → `flowmap.html` | `flowmap-artifact` |
| 4. 화면설계서 탭 | `sb-pages.js` | `sb-screen-spec` |
| 5. 디자인 캔버스 | `design/project/*.dc.html` | `design-canvas` |
| 6. 검수 · 게시 | 점검 0건, Artifact 링크 | `artifact-qa` |

## 프로젝트 폴더 만들기

```bash
cp -r <플러그인>/templates/project-starter  <작업폴더>/spec-kit      # 또는 examples/demo-park 를 복사해 고친다
python -I <플러그인>/scripts/build_kit.py <작업폴더>/spec-kit        # → spec-kit/flowmap.html
```
`kit.json`의 `docs`가 실제 문서 폴더를 가리키게 한다(프로젝트 저장소의 docs/를 그대로 써도 된다). 처음에는 예시(`examples/demo-park`)의 project.js · sb-pages.js를 열어 같은 모양으로 쓰는 것이 가장 빠르다.

## 사용자와 먼저 정할 것

- **범위 원칙**: 기존 기능을 유지하는지, 신규 기능을 실제 API · DB까지 만드는지 아니면 UI · 고정 데이터로만 만드는지. 문서 1장과 12장(서버 · DB)이 여기에 따라 달라진다.
- **산출물 용도**: 시연용이면 "시연" 표시를 넣고, 실제 개발 문서면 화면에 시연 · 예시 배지 · 안내 문구를 넣지 않는다.
- **참고 형식**: 사용자가 따르길 원하는 화면설계서 예시(PDF 등)가 있으면 그 문법을 먼저 분석한다(`sb-screen-spec`).
결정이 필요한 것은 한 번에 묻고, 기본값이 분명한 것은 정해서 진행하며 그렇게 했다고 알린다.

## 원칙

- **근거 우선**: 원본 자료와 배포 사이트에서 확인한 사실로 쓴다. 확인 못 한 것은 "확인 필요"로 표시하고 추측으로 채우지 않는다. 로그인이 필요한 사이트는 사용자가 직접 로그인한다(비밀번호를 대신 입력하지 않는다).
- **기존 사이트와 같은 톤**: 기획 PPT의 색 · 장식이 아니라 배포 사이트에서 잰 값(글꼴 · 색 · 카드 · 버튼 · 입력 높이 · 배지)으로 그린다. PPT는 항목 · 배치의 근거로만 쓴다.
- **요구 충족은 화면 단위로 본다**: 요구 항목이 기능 ID에 연결됐는지만이 아니라 그 입력 · 동작이 어느 화면 어디에 있는지 확인한다.
- **한 원본, 여러 산출물**: 시안은 project.js 한 곳에 쓰고 플로우 맵 · 화면설계서 · 디자인 캔버스(내보내기)가 모두 그것을 쓴다. 문서 표는 build가 읽어 넣는다.

## 자주 틀린 것

- 문자열 일괄 치환은 다른 화면의 같은 문자열까지 바꾼다. 치환 전 개수를 세고(`count == 1`) 문맥을 붙인다.
- 링크 공유 중인 Artifact는 게시하면 보는 사람에게 즉시 바뀐다. 게시가 "새 버전이 있다"며 거절되면 최신본을 읽어 비교 · 병합한 뒤 게시한다.
- 로컬 확인은 `python -m http.server --bind 127.0.0.1`로 연다(file:// 은 Chrome 확장이 못 열고, 검수 함수도 127.0.0.1에서만 켜진다).
- 다운로드한 런타임 · 외부 스크립트는 실행하지 않는다. 디자인 캔버스는 `templates/design/harness.html`로 해석해 점검한다.
- 기능 · 예외 · 검수를 추가하면 kit.json의 `expect`와 문서 변경 이력도 함께 고친다.

## 보고
